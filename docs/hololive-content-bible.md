# Hololive 內容骨架 v0

最近更新：2026-05-08

本文件是 `oshi-no-tower-godot` 的 Hololive 粉絲遊戲內容入口。目的不是一次定稿所有世界觀，而是先建立安全、可延續、可擴充的內容規則，避免卡牌、事件、遺物與敵人之後各自長成不同方向。

## 核心定位

`Oshi no Tower` 暫定為一座由直播記憶、舞台演出、粉絲文化與輕度謎因構成的塔。玩家不是在嚴肅黑暗世界裡求生，而是在可愛、熱鬧、帶一點失控感的粉絲向爬塔遊戲中，把牌組一步步整理成自己的推塔節奏。

內容語氣採以下方向：

- 可愛、粉絲向、輕度惡搞。
- 角色特徵要清楚，但不要需要長篇梗解釋才看得懂。
- 戰鬥可以有壓力，但整體不走沉重、恐怖或惡意黑暗路線。
- 謎因可以使用，但要服務玩法與辨識度，不要只是在堆梗。
- 卡牌、事件、遺物名稱要能單獨讓玩家猜到效果方向。

## 安全命名與內容規則

- 不直接使用歌詞、長篇台詞、逐字引用直播內容或需要精準授權的文字。
- 不把真實人物當成惡意敵人或負面描寫來源。
- 優先使用泛化後的粉絲文化語彙，例如「節奏」、「應援」、「舞台」、「直播事故感」、「粉絲 mascot」、「社團感」。
- 角色相關內容以正向特徵、常見形象與遊戲化抽象為主。
- 若某個梗需要玩家知道非常特定的來源才懂，先不要放進核心卡池，適合之後放事件或稀有遺物。
- 日文名稱可保留於角色名、Boss 名或特殊名詞；效果描述與 UI 預設繁體中文。

## 世界觀 v0

塔內每一層都像一段被重組的直播回憶：有舞台、有聊天室、有粉絲 mascot、有突然冒出的突發狀況。玩家選擇一位 playable 角色，以卡牌代表角色的節奏、技能、反應與粉絲向能力，在固定或未來隨機的路線中逐步推進。

目前 MVP 不需要完整劇情，只需要支撐以下內容：

- 普通戰：粉絲 mascot 或迷因化對手，用來測試基礎牌組。
- Boss 戰：大型謎因或混合概念，作為一段 run 的高壓收束。
- 寶箱 / 商店 / 篝火：先維持功能節點，未來再套 Hololive 主題文案。
- 事件與遺物：先在文件中定方向，等卡牌與獎勵流程穩定後再實作。

## 角色內容方向

### Subaru

Subaru 的內容主軸：鴨、吐槽、節奏、社團感、元氣防守。

玩法方向：

- 低費牌較多，能在同一回合打出多張牌。
- 多段攻擊與補刀感強。
- 防禦不是厚重龜縮，而是靠節奏、抽牌與能量微調維持行動。
- 適合做「越打越順」的節奏型卡池。

命名語氣：

- 可用「節奏」、「連打」、「吐槽」、「鴨式」、「聲援」、「重新站穩」等方向。
- 避免過度依賴單一梗，讓非重度粉絲也能看懂卡牌效果。

### Botan

Botan 的內容主軸：射擊、獅子、冷靜、精準、穩定防線。

玩法方向：

- 單張效率較高，尤其是攻擊與格擋。
- 節奏比 Subaru 慢，但更穩。
- 透過準備、標記、換彈、掩體等語彙建立射擊感。
- 適合做「少張高品質行動」與「防守後反擊」的卡池。

命名語氣：

- 可用「精準」、「點放」、「掩體」、「換彈」、「狙擊準備」、「火線」等方向。
- 效果描述要明確，不要把射擊感寫成看不懂的戰術黑話。

## 敵人與 Boss 定位

### SSRB

SSRB 是目前普通敵人的核心來源，也可作為巨大化 Boss 變體。

- SSRB Gray：基礎普通戰，測試玩家輸出節奏。
- SSRB Camouflage：加入防禦行動，測試玩家是否能處理格擋與攻防節奏。
- SSRB White：較高 HP 與重擊，測試玩家防禦與收尾能力。
- 巨大 SSRB 變體：可保留為 Boss pool，代表 mascot 概念被塔放大。

### スバルトダック

`スバルトダック` 是 Subaru / Botan 混合謎因 Boss，目前保留為隨機 Boss pool 的代表 Boss。

- 顯示上要保持 Boss 感：BOSS 標籤、暗色 overlay、1.5 倍顯示比例。
- 設計上可以偏「鴨 + 射擊 / 爆發」混合，但目前先不新增複雜 phase。
- 後續如果做 Boss gimmick，可讓它測試玩家對多段傷害與穩定防禦的掌握。

## 系統內容優先順序

1. 先穩定角色卡池與命名規則。
2. 再整理戰鬥獎勵，讓卡牌取得更接近正式 run。
3. 再做簡版 Hololive 主題 relic。
4. 再做簡版事件，先用固定事件或 debug event。
5. 最後再做隨機地圖，避免在內容池不足時就先做大量路線生成。

## 可接受的 v0 內容密度

- 每位角色先做到約 10-12 張可獎勵卡。
- 每位角色先有 2-3 個清楚 archetype 方向，不追求完整卡池。
- relic 先做 3-5 個，能驗證 hook 即可。
- event 先做 2-3 個，驗證選項、代價、獎勵即可。
- 地圖先保留固定路線，等事件 / 遺物 / 獎勵池有基本內容後再隨機化。
